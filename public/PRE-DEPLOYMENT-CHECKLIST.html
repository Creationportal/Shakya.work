13 · Hosting Runtime Readiness (Vercel / serverless)

Pass/api/contact — no 500 on read-only FS (FIXED this pass)
The contact route wrote .data/contact-messages.json inside a try/catch that returned 500 on failure. On serverless hosts (Vercel included) the filesystem is read-only at runtime (only /tmp is ephemerally writable) and .data/ is gitignored (not deployed) → the form would have looked broken. Persistence is now best-effort: the write is isolated in persistContact() and a failure returns {success:true, persisted:false} (HTTP 200). Verified by chmod-ing the data file 444: POST still returns 200 (no 500), persisted:false.
Pass/api/access-request — no 500 on read-only FS (FIXED this pass)
Same pattern as /api/contact: write isolated in persistAccessRequest(); on FS failure returns {ok:true, persisted:false} (HTTP 200) instead of 500. Verified with read-only data file → 200.
PassSettings store — saveSettings no longer throws (FIXED this pass)
saveSettings() previously did an unguarded fs.writeFileSync (called by PUT /api/settings). On a read-only serverless FS it would throw and 500 the settings save. Now wrapped in try/catch returning the normalized object — the API always acknowledges success; persistence simply no-ops on a read-only FS.
Pass/ideas/agent-operation-flow — SKILL.md read edge-safe (FIXED this pass)
The page did readFileSync(public/agent-operation-flow/SKILL.md) at request time. On serverless/edge runtimes the public asset is not reliably on the function's local FS (it would render "Skill file not found."). Now loadSkillText() tries disk first, then falls back to fetch()ing the same-origin static URL (https://{host}/agent-operation-flow/SKILL.md) — reliable on Vercel. Verified the page renders the skill block (200).
InfoVercel is the deployment target — no adapter needed (native Next.js 16)
The repo deploys to Vercel, which natively supports Next.js 16 — no output mode, no @cloudflare/next-on-pages / OpenNext adapter, no wrangler.toml (all removed). Vercel auto-detects the framework from package.json and runs next build; the existing scripts (dev/build/start) are correct. Deploy steps: push to the connected Git repo (auto-deploy) or use the vercel CLI; set env vars SETTINGS_PASSWORD, ACCESS_CODE, CV_GEO_LOOKUP in the Vercel project. Security headers from next.config.ts (headers()) are honored by Vercel.
PassContact / access-request now persist to Vercel KV when linked (FIXED this pass)
Added @vercel/kv (^3) + src/lib/kv.ts (getKv() returns the client only when KV_REST_API_URL + KV_REST_API_TOKEN are set, else null). /api/contact and /api/access-request persist durably via kv.rpush("contact_messages" | "access_requests", entry) when KV is linked. Without KV they fall back to the (read-only-safe) disk path and still return 200 — so the form never 500s. To enable durable storage: in the Vercel dashboard create a KV store and link it to the project (injects the two env vars); no code change needed. Free tier: 300K reads / 100K writes per day — ample for a portfolio.
